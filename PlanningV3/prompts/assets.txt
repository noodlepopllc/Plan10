This is the spec your converter must follow when turning the PASS 1 expansion output into registry.json.
⭐ 0. INPUT FORMAT (PASS 1 OUTPUT)

PASS 1 always produces these blocks:

    SETTING BLOCK

    CHARACTER BIOGRAPHY BLOCK

    LOCATION BLOCK

    Detailed staging zones

    Architectural shell

    Environment objects

    Stable views

The converter must treat PASS 1 as the complete physical truth.

The converter must not infer, invent, or reinterpret anything.
⭐ 1. WORLD SERIALIZATION RULES

The world{} object must be built only from the SETTING BLOCK.
world.theme

A short title summarizing the setting’s nature (e.g., “Near‑Future Domestic Apartment Interior”).
world.time_period

The explicit or implied time period stated in the SETTING BLOCK.
world.technology_level

The explicit or implied tech level stated in the SETTING BLOCK.
world.description

The full SETTING BLOCK text, unchanged.

NO summarization.
NO rewriting.
NO compression.
⭐ 2. CHARACTER SERIALIZATION RULES

For each character in the CHARACTER BIOGRAPHY BLOCK:
id

Sequential integer starting at 1.
name

Exact name from PASS 1.
alias_slug

Lowercase, underscores, alphanumeric only.
voice

MUST match PASS 1’s voice description.
Format:
Code

"gender, age, pitch[, accent][, whisper]"

No invented tokens.
identity

A short identity anchor derived from PASS 1:
Code

"<gender>, <hair silhouette>, <base clothing>"

appearance_prompt

10–20 words.
Must include:

    gender

    hair silhouette

    hair color

    base clothing (1–2 items)

    ethnicity/species

    android traits if applicable

NO props.
NO environment.
NO emotion.
NO story.
background_zone

Must match EXACTLY one zone_name from the LOCATION BLOCK’s staging zones.
zone_prompt

Must be the full zone description from PASS 1, unchanged.
⭐ 3. LOCATION + ZONE SERIALIZATION RULES

For each location in the LOCATION BLOCK:
name

Exact heading.
slug

Lowercase, underscores.
description

The architectural shell description from PASS 1, unchanged.
zones[]

This is the critical part.

PASS 1 outputs staging zones as numbered or named items under the staging‑zone section.

Example:
Code

1. Entrance Threshold
2. Main Interaction Area
3. Seating Zone
...

The converter must:

    Extract each staging zone as its own JSON object

    Ignore section headers like “A. Architectural Shell”, “B. Environment Objects”, etc.

    Use the zone heading as zone_name

    Use the full text under that heading as description

zone_name

Remove numbering:
Code

"1. Entrance Threshold" → "Entrance Threshold"

description

Copy the entire zone description EXACTLY as written:

    Function & Boundaries

    Visual Details

    Anchors

    Any additional lines

NO summarization.
NO rewriting.
NO merging.
notable_details[]

If PASS 1 includes a numbered or bulleted list of notable details, copy each item verbatim.
⭐ 4. OUTPUT JSON STRUCTURE

The converter must output:
Code

{
  "world": {
    "theme": "...",
    "time_period": "...",
    "technology_level": "...",
    "description": "..."
  },
  "characters": [
    {
      "id": 1,
      "name": "...",
      "alias_slug": "...",
      "voice": "...",
      "identity": "...",
      "appearance_prompt": "...",
      "background_zone": "...",
      "zone_prompt": "..."
    }
  ],
  "locations": [
    {
      "name": "...",
      "slug": "...",
      "description": "...",
      "zones": [
        {
          "zone_name": "...",
          "description": "..."
        }
      ],
      "notable_details": [
        "detail 1",
        "detail 2"
      ]
    }
  ],
  "scenes": []
}

⭐ 5. PROHIBITIONS

The converter MUST NOT:

    invent characters

    invent locations

    invent zones

    modify PASS 1 text

    summarize or compress descriptions

    treat section headers as zones

    merge multiple zones

    add props, story events, or emotional content

    alter time period or tech level

    infer geometry or staging

⭐ 6. OUTPUT RULES

    Output ONLY valid JSON.

    No commentary.

    No markdown.

    No explanations.
