⭐ PASS 2 — JSON ARC GENERATOR (FINAL SPEC)

(This replaces the old PASS 2 beat‑block format completely.)

PASS 2 receives validated beats and outputs JSON with:

    original actions (preserved)

    a new continuous motion arc

    a neutral starting description

    dialog untouched

    posture untouched

    tone untouched

    head_gesture untouched

PASS 2 does not perform continuity analysis.
PASS 2 does not output beat blocks.
PASS 2 does not output YAML‑style structures.
PASS 2 outputs JSON only.
⭐ PASS 2 — INPUT CONTRACT

PASS 2 receives a beat with:

    beat number

    zone

    actions (validated list of physical actions)

    dialog

    posture

    head_gesture

    tone

PASS 2 does not receive raw narrative.
PASS 2 does not receive unvalidated actions.
⭐ PASS 2 — OUTPUT CONTRACT (JSON)

PASS 2 MUST output the following JSON object per beat:
json

{
  "beat": <number>,
  "zone": "<zone>",

  "starting_description": {
    "<Character>": "<neutral physical description>",
    ...
  },

  "actions": [
    "<original validated action>",
    ...
  ],

  "arc": "<continuous motion arc>",

  "dialog": [
    {
      "speaker": "<name>",
      "line": "<exact dialog>"
    }
  ],

  "posture": {
    "<Character>": "<posture>",
    ...
  },

  "head_gesture": {
    "<Character>": "<gesture>",
    ...
  },

  "tone": {
    "<Character>": "<tone>",
    ...
  }
}

⭐ PASS 2 — STEP 1: STARTING DESCRIPTION

PASS 2 MUST generate:
Code

starting_description:
  <Character>: <neutral physical description>

Rules:

    one entry per character

    reflect posture

    include objects explicitly held in the first physical action

    no motion

    no emotion

    no inference

    no micro‑gestures

Examples:

    "standing, holding rag"

    "leaning, holding tankard"

    "sitting"

⭐ PASS 2 — STEP 2: ARC GENERATION (HARD OVERRIDE)

PASS 2 MUST generate a single continuous motion arc from the validated actions.

Rules:

    preserve meaning

    preserve order

    preserve identity

    preserve posture

    no emotion

    no dialog

    no new objects

    no inference

    no micro‑gestures

    no head‑gesture actions

    no facial actions

    no narrative verbs

    no mental verbs

    no state verbs

    no speech verbs

PASS 2 MUST output:
Code

"arc": "<continuous motion arc>"

PASS 2 MUST NOT:

    output multiple arc actions

    output comma‑joined actions

    output original action text

    output the beat‑block format

⭐ PASS 2 — STEP 3: PRESERVE ORIGINAL ACTIONS

PASS 2 MUST preserve the validated actions: list exactly as received.

These are used for:

    debugging

    continuity

    object tracking

    visibility analysis

PASS 2 MUST NOT modify the original action strings.
⭐ PASS 2 — STEP 4: PRESERVE DIALOG, POSTURE, TONE, HEAD_GESTURE

PASS 2 MUST NOT modify:

    dialog

    posture

    tone

    head_gesture

These fields are copied directly into the JSON output.
⭐ PASS 2 — NO CONTINUITY ANALYSIS

PASS 2 MUST NOT:

    detect teleportation

    detect object introduction

    reorder actions

    analyze visibility

    generate continuity metadata

Those belong to a separate continuity engine (if you still want one).

PASS 2 MUST output a JSON array containing one JSON object per beat.

PASS 2 MUST NOT output beats individually.
PASS 2 MUST NOT wrap the array in any additional structure.
PASS 2 MUST NOT stop after the first beat.
